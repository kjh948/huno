# ESP32-S3 기반 HUNO 펌웨어 구현 상세 (GankenKun 포팅)

이 문서는 기존 `kjh948/huno` 오픈소스 펌웨어를 기반으로 작성된 **ESP32-S3 기반 ZMP 동적 보행 펌웨어**의 설계 및 구현 내용을 상세히 설명합니다. (프로젝트 소스코드: `esp32_firmware/` 폴더)

---

## 1. 펌웨어 시스템 아키텍처 (멀티코어 설계)

GankenKun과 같은 ZMP(영모멘트점) 기반 보행 제어는 주기적이고 매우 정밀한 제어 루프를 요구합니다. 통신(Wi-Fi)이나 웹 서버 처리로 인해 보행 루프에 수 밀리초(ms)의 딜레이가 발생하면 로봇은 즉시 균형을 잃고 넘어지게 됩니다.
이를 방지하기 위해 ESP32-S3의 두 개의 코어(Core 0, Core 1)를 완벽히 분리하여 역할을 할당했습니다.

### 1.1 Core 1 (애플리케이션 코어) - 보행 제어 전담
*   **구현 방법:** `xTaskCreatePinnedToCore`를 사용하여 `walkTask`라는 FreeRTOS 태스크를 생성하고 이를 **Core 1**에 고정(Pin)시켰습니다.
*   **정밀한 타이밍 제어:** 기존 `delay()` 함수 대신 FreeRTOS의 `vTaskDelayUntil()`을 사용하여, 루프 내부의 계산 시간에 상관없이 **정확히 10ms(100Hz)** 마다 주기적으로 `walkEngine.update()`가 호출되도록 구현했습니다.
*   **수행 역할:** 역기구학(IK) 계산, 상태 공간 방정식(CoM 위치) 계산, 모터 UART 통신 제어.

### 1.2 Core 0 (프로토콜 코어) - 통신 및 CLI 전담
*   **구현 방법:** 아두이노 프레임워크의 기본 `loop()` 함수가 실행되는 코어입니다. (ESP32의 Wi-Fi 스택과 기본 네트워크 처리도 이 코어에서 동작합니다.)
*   **비동기 처리:** `Serial.available()`과 `WebSerial.onMessage`를 통해 외부 명령을 비동기적으로 수신합니다.
*   **수행 역할:** Wi-Fi 연결 관리, WebSerial 인터페이스 구동, 사용자 터미널 CLI 명령어(`start`, `stop`, `f` 파라미터 조절 등) 파싱.

## 2. GankenKun 보행 알고리즘 이식 (`PK.cpp`)

파이썬 환경의 시뮬레이션 코드(`preview_control.py`)를 임베디드 C++ 환경으로 최적화하여 번역했습니다.

### 2.1 상태 공간 모델 (State-Space Model) 배열 연산
파이썬의 `Numpy`를 이용한 행렬 곱셈 연산을 가벼운 C++ 1차원/2차원 배열과 `for`문 기반의 스칼라 연산으로 변환했습니다.
```cpp
// PK.cpp 내의 무게중심(CoM) 업데이트 로직
for (int i=0; i<3; i++) {
    next_com_x[i] = A_d[i][0]*com_x[0] + A_d[i][1]*com_x[1] + A_d[i][2]*com_x[2] + B_d[i]*u_x;
    // Y축도 동일하게 계산
}
```
메모리 동적 할당(`malloc`)이나 무거운 행렬 클래스(`Eigen` 등) 없이 순수 배열 연산을 사용함으로써, 메모리 파편화를 방지하고 연산 속도를 극대화했습니다.

### 2.2 제어 게인(Gain)의 오프라인 상수화 (Hardcoding)
가장 연산량이 많은 Riccati 방정식(DARE) 풀이는 임베디드 칩 내부에서 실시간으로 처리할 수 없습니다. 
따라서 Python에서 미리 계산된 제어 게인 행렬(`F` 행렬 및 `f_gain` 배열)을 추출한 뒤, `PK.cpp` 파일 상단에 `const float` 상수로 선언해 두었습니다. 
이를 통해 ESP32-S3는 단 한 번의 복잡한 궤적 방정식 풀이 없이, 이미 풀이된 정답(상수)을 불러와 곱셈 연산만 수행하므로 매우 빠르게 ZMP를 쫓아갈 수 있습니다.

### 2.3 논블로킹(Non-blocking) 궤적 제어
기존 로봇의 모션 코드는 `delay(20)`을 남용하여 모터가 목적지에 도달할 때까지 코드 실행을 멈추는(Blocking) 방식이었습니다.
포팅된 코드는 모든 `delay`를 제거하고, 매 10ms 호출 순간의 타겟 각도만 계산해 모터에 패킷을 쏘고 바로 함수를 종료합니다. 즉, 상태 기계(State Machine) 방식으로 전환되었습니다.

## 3. 웹 및 CLI 인터페이스 (WebSerial)

기존 저장소의 훌륭한 장점인 사용자 제어 인터페이스 구조를 그대로 유지했습니다.

*   **CLI 명령체계 통일:** USB 시리얼 터미널 창과, 브라우저로 접속하는 WebSerial 화면 두 곳에서 완벽히 동일한 명령 체계(예: `w` 입력 시 걷기 시작, `sh 0.5` 입력 시 발 들기 높이 파라미터 실시간 튜닝)가 작동합니다.
*   **안전한 데이터 공유:** Core 0에서 CLI를 통해 파라미터 변수(`walkEngine.f`, `walkEngine.step_height` 등)를 수정하면, Core 1에서 돌아가는 보행 태스크가 실시간으로 변경된 변수를 참조하여 즉각적으로 보행 패턴(보폭, 속도 등)을 부드럽게 변경합니다.
