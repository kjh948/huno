# HUNO (ESP32-S3) + GankenKun 보행 알고리즘 통합 가이드

이 문서는 [kjh948/huno/esp32s3](https://github.com/kjh948/huno/tree/main/esp32s3) 저장소의 기본 오픈루프(Sine wave 기반) 보행 코드를 GankenKun의 **ZMP/Preview Control 기반 동적 보행 알고리즘**으로 대체(포팅)하기 위한 구현 방법 및 필요 하드웨어 구성을 정리한 가이드입니다.

---

## 1. 하드웨어(HW) 구성 요구사항

보행 제어 알고리즘의 고도화 수준에 따라 하드웨어 구성을 3단계로 나누어 정리했습니다.

### 1.1 기본 구성 (오픈루프 ZMP 제어용)
ESP32-S3를 메인 두뇌로 사용하여 최소한의 걷기 동작을 수행하기 위한 필수 하드웨어입니다.

| 부품 | 설명 | 비고 |
| :--- | :--- | :--- |
| **메인 컨트롤러** | ESP32-S3-DevKitC-1 | Wi-Fi 통신(WebSerial) 및 보행 제어 알고리즘 연산 수행. 4MB Flash / 2MB PSRAM 권장. |
| **액추에이터** | WCK 서보모터 (약 16개) | HUNO 로봇의 기본 모터. 데이지 체인(Daisy-chain) 방식의 UART 통신 지원. |
| **통신 인터페이스** | UART 결선 (TX, RX) | ESP32-S3의 하드웨어 Serial1(RX: 6, TX: 5)을 WCK 모터의 통신선에 연결. |
| **전원 공급 장치** | 2S Li-Po 배터리 (7.4V) | WCK 모터 구동용 메인 전원. |
| **전압 레귤레이터 (UBEC)** | 5V / 3A 강하 모듈 | 7.4V 배터리 전원을 5V로 강하하여 ESP32-S3 보드에 안정적으로 공급. |

> **주의사항:** WCK 서보모터의 데이터 라인(TX/RX) 전압 레벨과 ESP32-S3(3.3V)의 로직 레벨이 일치하는지 확인해야 합니다. 필요시 로직 레벨 컨버터(Logic Level Converter)가 필요할 수 있습니다.

---

### 1.2 폐루프 제어 구성 1: IMU 추가 (외란 보상 및 자세 안정화)
오픈루프 방식은 모델 오차나 바닥의 마찰 차이로 인해 로봇이 넘어질 수 있습니다. 이를 보완하기 위해 로봇의 기울기를 실시간으로 감지하는 센서를 추가합니다.

| 부품 | 추천 모델 | 연결 방식 및 용도 |
| :--- | :--- | :--- |
| **관성 측정 장치(IMU)** | MPU6050(6축) 또는 BNO085(9축) | **I2C 통신 (SDA, SCL)**. 로봇의 몸통(골반 부근)에 부착하여 현재 로봇의 Roll, Pitch, Yaw 기울기와 가속도를 측정합니다. |

*   **제어 활용 방안:** 알고리즘이 예측한 몸통 기울기와 IMU가 측정한 실제 기울기의 오차를 구한 뒤, 발목 모터(Ankle Roll/Pitch)의 각도를 실시간으로 미세 조정하여 로봇이 중심을 잃지 않게 밸런싱(Stabilization)합니다.

---

### 1.3 폐루프 제어 구성 2: FSR 추가 (실제 ZMP 측정 및 착지 감지)
Preview Control이 지시하는 '목표 ZMP'와 로봇이 실제로 딛고 있는 '실제 ZMP'가 일치하는지 확인하려면 발바닥에 압력 센서가 필요합니다.

| 부품 | 추천 모델 | 연결 방식 및 용도 |
| :--- | :--- | :--- |
| **압력 센서 (FSR)** | FSR402 (발당 2개 또는 4개) | **아날로그 입력 (ADC)**. 발바닥에 부착하여 지면 반발력을 측정합니다. |
| **(선택) ADC 확장 보드** | ADS1115 (16비트 ADC) | **I2C 통신**. ESP32의 내장 ADC 노이즈가 심할 경우, 정밀한 압력 측정을 위해 I2C 기반의 외부 ADC 보드를 거쳐 연결합니다. |

*   **센서 부착 전략 (2개 vs 4개):**
    *   **발당 2개 (앞꿈치/뒤꿈치):** 배선이 간단하고 ESP32의 내장 ADC만으로도 충분히 커버 가능합니다. 전후(Pitch) 방향의 ZMP 추정과 착지 감지(Touch-down)에 완벽하게 동작하며, 소형 휴머노이드(HUNO 등)에 가장 **가성비와 효율이 좋은 추천 방식**입니다. (단, 좌우 측면 ZMP 측정은 불가능)
    *   **발당 4개 (네 모서리):** 전후(Pitch) 및 좌우(Roll) 방향의 ZMP를 모두 정밀하게 측정할 수 있습니다. 단, 총 8개의 ADC 채널이 필요하여 배선이 복잡해집니다.

*   **제어 활용 방안:** 
    1. **ZMP 제어:** 각 센서의 압력 분포를 수식으로 계산하여 현재 로봇의 '실제 ZMP' 위치(X, Y)를 실시간으로 알아냅니다. 목표 ZMP와의 오차를 CoM 궤적 계산에 피드백합니다.
    2. **착지 감지(Touch-down):** 스윙 중인 발이 바닥에 닿는 순간을 충격량으로 감지하여, 보행 주기의 타이밍(Phase)을 강제로 동기화하고 충격을 흡수하도록 무릎을 살짝 굽히는(Compliance) 제어에 활용합니다.

## 2. GankenKun 알고리즘 구현 및 포팅 계획

현재 `huno/esp32s3` 저장소의 보행 제어는 `PK.cpp`의 `update()` 함수에서 `sin(t)` 함수를 이용한 단순 하드코딩 패턴으로 구현되어 있습니다. 이를 GankenKun의 ZMP 기반 제어로 변경해야 합니다.

### 단계 2.1: 제어 주기(Real-time Loop) 고도화
현재 `esp32s3.ino`의 `loop()` 안에서 `walkEngine.update()`가 호출되며 내부에 `delay(20)`이 섞여 있습니다. 동적 보행의 안정성을 위해 타이머 인터럽트로 교체합니다.
- **수정안:** ESP32의 하드웨어 타이머를 설정하여 정확히 `10ms (100Hz)` 마다 역기구학 연산과 모터 패킷 전송을 실행하도록 변경합니다.

### 단계 2.2: 역기구학(IK) C++ 번역 (`kinematics.py` ➡️ `PK.cpp`)
현재 `PK.cpp`의 `left_leg()`와 `right_leg()` 함수는 관절에 직접 각도 비율을 더하는 방식을 씁니다.
- **수정안:** `kinematics.py`의 `solve_ik()` 함수에 있는 6자유도 삼각함수 공식(atan2, acos 등)을 `<math.h>`를 활용해 C++로 번역하여 `PK.cpp`에 덮어씌웁니다. HUNO 로봇의 다리 링크 길이(허벅지, 종아리 길이)를 실측하여 `L1`, `L2` 상수를 교체해야 합니다.

### 단계 2.3: ZMP Preview Control 상수 하드코딩
GankenKun 파이썬 코드의 `scipy.linalg.solve_discrete_are` 연산은 ESP32에서 실시간으로 돌리기 무겁습니다.
- **수정안:** 파이썬(PC)에서 `preview_control.py`를 실행해 출력되는 최적 제어 게인 행렬(`F` 행렬, `f` 배열) 값들을 복사하여 `PK.cpp` 상단에 `const float` 배열 상수로 선언합니다.

### 단계 2.4: 행렬 연산 기반의 보행 상태 업데이트
기존 `PK::update()`의 Sine wave 궤적을 폐기하고, 파이썬의 `preview_control.py`에 있는 `set_param()` 로직을 이식합니다.
- **구현 로직:**
  1. `foot_step_planner` C++ 함수를 통해 딛어야 할 목표 발 위치(Goal X, Y, Th) 배열 생성.
  2. 매 루프(10ms)마다 상태 공간 행렬 연산(`x_next = A * x + B * u`)을 C++ `for`문을 통해 수행하여 무게중심(CoM)의 다음 위치 계산.
  3. 스윙하는 발의 포물선 궤적(Foot Trajectory) 계산.
  4. 계산된 CoM과 스윙 발의 위치를 **단계 2.2**의 IK 함수에 넣어 최종 모터 각도 16개 산출.
  5. `_wck->posGroup()` 함수를 통해 서보모터로 각도 전송.

## 3. 요약 및 기대 효과
이러한 방식으로 포팅하면, 기존 HUNO 로봇이 단순히 정해진 춤을 추는 수준을 넘어, **목표 좌표(X, Y)를 주면 넘어지지 않기 위해 스스로 무게 중심을 이동시키며 능동적으로 걸어가는 진정한 이족보행 로봇**으로 업그레이드될 것입니다. WebSerial을 통해 `w 0.5 0.2` (X로 0.5m, Y로 0.2m 이동) 같은 동적 명령을 즉각적으로 처리할 수 있게 됩니다.
